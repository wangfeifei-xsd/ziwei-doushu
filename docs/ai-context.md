# AI 解读上下文

Web 的 `/api/interpret` 与原生 App 共用 `packages/features/src/ai/prompts.ts`。两端先校验命盘，再由 `context.ts` 按字段白名单构建模型资料。

## 单盘提问

请求包含 `chart`、`messages`，以及可选的 `selection`：

```json
{
  "selection": {
    "view": "liunian",
    "liunianYear": 2027,
    "topic": "wealth",
    "palaceBranch": 5,
    "siHua": { "starName": "太阴", "siHua": "禄", "view": "liunian" }
  }
}
```

`view` 可取 `mingpan`、`daxian`、`liunian`。`topic` 可取 `overview`（命格）、`love`（感情）、`career`（事业）、`wealth`（财运）、`health`（健康）、`personality`（性格）。`topic`、`palaceBranch`、`siHua` 可省略；四化必须符合当前视图，切换年份/视图时页面清除旧四化选择。不传 `selection` 时使用本命视图及上海时区当前农历年。

页面首次载入、主题按钮和推荐卡片、宫位/四化选择、本命/大限/流年切换及年份调整，都只更新下一次提问的上下文。只有输入非空问题后点击「提问」或按回车才发送；中文输入法选字中的回车不发送。回答期间可继续修改选择，回答结束不会自动补发问题。

模型每次收到系统规则、结构化资料、当前会话的全部已完成历史问答和本次手动问题。不设单条消息 12000 字符、学习输入及合盘问题 4000 字符限制；保留角色、类型和非空校验，整包容量见下文。结构化资料包含：

- 公历排盘日、时辰、性别、可用的原始钟表时间与闰月口径；农历日期和两套四柱。
- 五行局、命宫、身宫、命主星、身主星、阴阳性别和虚岁。
- 十二宫宫干、星曜、本命四化、亮度、大限年龄段、三方四正、空宫与借星关系。
- 全部大限区间、现实当前大限、当前流年、所选流年及其所属大限；运限十二宫对应的本命宫位和来源独立的四化叠层。
- 格局名称、描述、等级、涉及宫位、成立/加分/破格条件及规则注明的出处。
- 所选主题、运限、年份、宫位及四化；根据本次问题和这些选择检索出的仓库文献条目，最多 6 条，正文总计不超过 3600 字符。

出生姓名、城市、客户端任意附加字段不会经命盘资料透传；用户主动写进问题里的内容仍属于聊天记录。每条用户消息附带提交时的运限、年份、宫位、四化和主题快照，避免后续选择变化改写旧问题的含义。所选内容用于补充上下文，以用户手动输入的问题为准。

## 运限口径与资料范围

虚岁按农历年差加一，流年以正月初一换年。流年命宫取太岁地支，大限命宫取所属大限宫位；四化叠层沿用页面的共享领域算法。童限和超出已有大限范围时，不回退到现实当前大限。

本实现提供运限宫位映射和四化叠层，未补造独立流曜或流月/流日/流时排盘。文献使用已有公版古籍整理库，含摘录与现代说明，不标称已逐字校勘原典。每条带书名、章节、段落 ID 与阅读页链接；界面只把库中真实存在的段落渲染为可点击引用。

合盘使用同一上下文构建器，结构化资料包含 `chartA`、`chartB` 和 `references`，并由宿主补入 `dataset`。双方资料与当前问题分开组织，已完成的问答按原顺序作为独立消息传递；失败或主动停止的部分回答不进入模型历史。这里的提示词和检索逻辑是本地实现，不依赖上游未公开的商业断语库。

## 命盘学习

Web `/learn` 与原生 `/#/learn` 共用学习页面。目录 `packages/domain/src/ziwei/learning-cases.ts` 提供十组教学合成生辰；每组特点均由排盘回归验证，不对应名人或真实经历。子时日期指已经确定的排盘日，不再执行钟表时刻换日或真太阳时换算。

学习请求沿用单盘接口，并增加 `learningCaseId`。共用消息构建器核对例盘编号与出生年月日、时辰、性别，再从目录重新排盘；客户端改写的星曜和课程说明不会成为教学依据。除完整单盘上下文外，增加 `learning`：例盘编号、主题、特点、学习要点、十四主星基础说明及排盘口径。提示词要求按盘面事实、术语、推导过程、条件与限制讲解。

进入页面、切换示例或视图、点选宫位与四化、填入推荐问题均不自动调用模型；仅发送问题时发起请求。每条问题保留当时的范围，最新选择决定本次上下文。切换例盘会终止请求并重置对话、输入及宫位/运限选择；停止或失败的回答不进入后续模型历史，同一例盘已完成的全部对话都会带入后续提问。

## 验证

`npm run test:ai` 覆盖上下文遗漏、运限映射交叉校验、春节/童限边界、非法选择、主题检索、引用溯源、字段白名单与完整历史。浏览器用例中的“AI 上下文”覆盖 Web 实际上游请求、原生 Responses 请求、选择不自动发送、输入法回车保护、跨年份追问、四化与宫位选择、长会话和引用跳转。

## 本地压缩样本资料

Web 和原生宿主在消息校验后按出生键检索 v4.0 资料，按需流式解码，32 条内存缓存。单盘和学习例盘每次注入一条完整记录；合盘分别注入甲、乙两条，双方同生辰时也分别保留人物归属。出生键为 `YYYY-MM-DD-hour-gender`，月日补零，时辰为不补零的 `0–11`，性别为 `male` / `female`；使用当前排盘日与时辰，不改用原始钟表日期。

`dataset` 按人物记录组织，包含 `person`、`key`、`status`、`version`、`generatedAt`、`engineCommit`、`source`、`licenses`、`integrity` 和 `topics`。13 个专题依次为 overview、personality、love、career、wealth、health、family、children、move、friends、home、spirit、parents。每个专题提供 `topic`、`title` 和直接取自 `record.c[topic]` 的原始 `text`。

正文不受段数、字符预算、段长、关键词或去重规则限制；标题、短段、长段、重复、原始空白和历史断语均保留。同一出生键的正文不随问题、主题、宫位和运限选择变化，由模型处理完整资料。古籍条目的独立检索实现仍保留其原有 6 条 / 3600 字符边界。

`integrity` 记录 expectedTopics、actualTopics、sourceCharacters、injectedCharacters 和 complete；字符数使用 JavaScript UTF-16 长度，不等于 UTF-8 字节数或 token 数。13 项正文均存在且非空才显示“已加载 13/13 个专题”。缺少专题时不发送部分正文，明确报告“资料不完整”；缺失、超覆盖年份、损坏和读取超时分别标注实际状态。模型和界面都获得状态，但状态事件只携带人物、出生键、数量、长度与原因，不重复传输正文或写入常规日志。

档案标明 2026-10-15 生成日期、旧引擎 `c25dd495`、数据版本 `ca268829f7a9` 以及主体和内嵌引文的许可。当前结构化命盘和所选时间为本次事实依据；档案是历史模板生成文本，不能当成真实经历，冲突须解释来源与差异。引用使用出生键、专题和版本，不生成档案站内链接；古籍引用仍链接已有阅读页。详见 [资料分发与场景入口](dataset-v4-usage-analysis.md)。

## 请求、输出与超时

Web 流式读取入站请求，并检查注入全文后的最终请求；原生 Rust 检查最终序列化请求。两端默认资源保护上限均为 **16 MiB**，可在模型设置中修改。超过时明确报错，保留问题；不删专题、不裁剪历史、不生成摘要或减少资料重试。浏览器入站与服务商请求容量是两个边界，模型的上下文窗口另由服务商决定。

模型设置中的“输出 token 额度”可留空；此时 Chat Completions 和 Responses 均不强制发送输出额度，由服务商默认设置生效。填写后分别使用 `max_completion_tokens` / `max_output_tokens`，原生转发不会再覆盖成 4096。提示词按问题复杂度充分解释，不再要求固定 600–1000 字。服务商自身的输出上限仍然生效。

正常解读默认整体等待 **600 秒**，可以配置；连接测试独立为 **30 秒**。单盘、学习和合盘均支持主动停止及离开页面取消。Web 的整体计时包含请求读取与档案加载；原生 Rust 对模型传输计时，档案读取另有 20 秒保护。反向代理或托管平台自身的时长、请求大小限制需要相应配置，应用配置不能覆盖外部限制。

容量超限、模型上下文不足、输出参数不兼容、输出额度耗尽、连接中断和缺少完成信号分别报告。部分回答标记未完成，问题保留供调整配置后重试，不把失败伪装成成功。

`npm run test:dataset` 验证十组真实记录逐专题相等及不选段；`npm run test:ai`、`test:model-config`、`test:shared` 和 `test:native` 验证容量、双协议、可选额度、状态、取消及错误。浏览器回归核对实际 Web 上游与原生 IPC 中的全文和超过旧 256 KiB 的请求。程序测试不代替真实模型回答的人工质量评估。
