# 档案保存与离线维护

网站继续使用 H2；四端应用使用设备私有目录的 SQLite。安装应用不会自动读取网站数据库，也不自动同步其他设备。本轮没有搬动、清空或覆盖既有 `data/`。

当前 Web 与原生应用的档案页提供创建、编辑、搜索和删除，不再提供档案导入、导出。命盘图片与链接分享仍可使用。下文的命令行工具供维护旧网站数据使用，不是应用中的迁移入口。

## 从 H2 只读导出

1. 停止使用原数据库的网站服务：`./scripts/stop.sh web` 或 `.\scripts\stop.ps1 web`。对独立部署服务，先通过其进程管理器正常关闭。
2. 备份原 `data/` 目录到私密位置。模型文件可能含 API Key，不能上传 GitHub。
3. 根目录执行下面命令，显式指定**原数据库所在目录**与**不存在的输出文件**：

```sh
npm run export:h2 -- --data-dir '/原项目/data' --out '/备份/紫微档案-20261031.json'
```

工具要求 `ziwei.mv.db` 已存在，以 `IFEXISTS=TRUE;ACCESS_MODE_DATA=r` 打开，不创建表、不写数据库，检测占用锁；输出使用独占创建，拒绝覆盖既有备份。失败不会删除原库。必须安装 Java 17+ JDK。缺目录或数据库、权限不足、仍有服务占用时先纠正问题，不能用新建空库代替原数据。

该命令行工具只导出档案，不包含 AI 配置、API Key、Stronghold 密码、历史缓存或用户主题。

## 旧档案格式

维护工具输出的格式标识为 `format: "ziwei-profiles"`，当前 `version: 1`。格式校验最多接受 10,000 份；未知版本、重复/伪造 ID、非法日期、无效时间戳均被拒绝。应用界面不提供读取此文件的入口。

档案 ID 仍为固定顺序、规范化表单 JSON 的 SHA-256；不是随机 UUID。编辑导致 ID 改变时原子替换，冲突时拒绝覆盖。H2 与 SQLite 共用跨语言 golden fixture 核验字段顺序及摘要。

生辰保存的是原始钟表时间。真太阳时、未知时辰和晚子时规则在起盘时按已有算法处理，不把已经换日或校正过的结果写回原始资料。

## 应用备份与恢复

应用私有数据由 Tauri `app_data_dir()` 定位，标识目前为 `com.ziwei.chart`：

- macOS 通常为 `~/Library/Application Support/com.ziwei.chart/`。
- Windows 通常位于用户 AppData/Roaming 下的同名应用目录。
- Android/iOS 位于应用沙盒，普通文件管理器不一定可访问。

文件包括 `ziwei.sqlite`（WAL 期间还可能有 `-wal`、`-shm`）、`secrets/model.hold`、`secrets/model.salt`。需要完整私有备份时先退出应用，再复制整个目录；不要在数据库打开时单独复制主文件。移动端沙盒的访问和备份受系统限制，卸载或清除应用数据可能删除本地档案。

Stronghold 的 `.hold` 与 `.salt` 必须一起备份，且仍需原解锁密码；忘记密码不能恢复 Key，可清除密钥库后重新配置。密码从不落盘，档案维护工具不会迁移模型密钥。

## 异常恢复

初始化/升级失败会显示错误并保留原文件，不会自动删库“重置”。退出应用，保留故障副本和完整备份，再排查权限、空间、schema 版本。修复成功后重新启动；确需恢复时只在应用关闭后用经过确认的备份替换整个目录。不要把含私人档案/密钥的数据库或日志放入公开 issue。

SQLite 使用版本化 SQL migration，包含旧 schema fixture 升级和损坏文件保留测试。数据库升级不是 JSON 格式版本升级，两者各自校验。
