## 数据实际能提供的内容

每条记录包含 k、y、m、d、h、g、ms、t、c。k 是“公历日期-时辰序号-性别”，h 为 0–11 的十二时辰索引，ms 是命宫首颗主星或 null，t 为各专题字数，c 是十三专题的 Markdown 文本。

**缺少完整十二宫结构、明确格局标签、真实人物经历和配对结果。** 排盘与格局识别仍需由当前引擎完成。它由上游排盘引擎与断语库确定性批量生成；可以作为解释资料和旧版本输出样本，不能当成真实生活结果的观测数据库。

当前源码 [db-analysis.ts](/Users/wanghongfei/work/work-space/ziwei-doushu/packages/domain/src/ziwei/db-analysis.ts:54) 的 STAR_DB 为空。可以用样本和已有古籍整理新的内容页面，但不能将一张盘的综合断语直接当通用星义，也不能据此声称已经找回上游私有断语模板与完整后台。

## 决定接入方式的实际发现

**小型教学缓存已经可行。** 十条完整记录合计 868,280 字节；目前只是审计提取文件，尚未成为应用运行时缓存。没有必要把全部归档送进浏览器或每次问答都传十三篇全文。

**亮度版本差异已观测到。** 天同化忌例盘在当前引擎中为“平”，样本总论为“庙旺”；紫府例盘的天府当前为“得”，样本写“庙旺”；日月例盘的太阳当前为“得”、太阴为“不”，样本用“庙旺／落陷”。上游 [README 的版本说明](/Users/wanghongfei/work/work-space/ziwei-doushu/README.md:84) 也明确记载：10-15 数据使用旧默认“现代修正 v2”，10-20 后默认改为《斗数全书》。样本文字还存在亮度分组表达，不能只凭文字逐字比较判断引擎对错。需保留配置并对冲突句逐段处理；不应静默将应用切回旧流派。

**时间快照需要过滤。** 十条记录都包含“2026”字样，其中天同化忌记录出现“当前大限(35-44岁)走【田宅宫】”；1990 年 8,760 条中有 3,333 条含字面“当前大限”。“含 2026”只说明存在该字样，不代表每段都属于流年分析。虽然上游将其描述为本命解读，实际文本仍混有时间语句，因此用户选择 2027 或其他运限时必须按当前算法重新计算。仅删除“2026”几个字符不够，应排除整条不适用论述，或在明确的历史阅读模式下标注基准时间。

**重复文本很多，宜先去重再建搜索库。** 1990 年按空行分段、去除首尾空白后，记录到 3,853,953 次段落出现，只有 53,968 个不同段落，精确重复出现率为 98.60%。这个值包括重复标题和套话，只是单年精确文本统计，不是全库语义重复率，也不等于只剩 53,968 条命理知识。无需给 877 万篇专题全文立即逐篇生成向量。

**流式查找适合验证和低频需求，生产服务需要缓存。** 本机单次测试中，年初例盘查找耗时 0.034–0.207 秒，2001-07-21 例盘耗时 1.010 秒、扫描 4,830 条、流式处理约 391.8 MB 原文。1990 年完整 JSON 解析和段落哈希审计耗时 6.929 秒，处理约 742.0 MB 原文。原文没有整年保存到磁盘。

这些耗时不含网络和 tar 成员复制，不是 P95，也不能据此承诺线上响应速度。每年约 2 MB 的压缩数据仍可能解码成数百 MB 文本，存在 CPU 和解码内存成本。tar 位置索引只解决“年份在哪里”，普通 zstd 流不能直接按出生键随机跳转。

## 24 个利用场景

优先级：P0 为建议第一阶段；P1 为下一阶段；P2 为有明确需求再做；P3 为研究储备。成本“小／中／大”是相对实现工作量，不是工期承诺。P0 包含学习功能所依赖的质量检查和缓存机制。

### 问答与阅读

**01. 十张教学盘的资料问答｜P0｜成本：小**

直接增强现有 /learn；回答能引用选中例盘的专题解读。

- 例子：选中天同化忌盘，问：化忌为什么不等于一切都不好？
- 实现：用已提取的十条记录作为缓存，按问题与所选宫位提取相关段落，并附生辰键、专题、版本和来源。
- 边界：十盘共 868,280 字节，均有 13 专题；应剔除与当前引擎冲突的亮度断语及不适用的时间句。

**02. 个人命盘的精确匹配问答｜P1｜成本：中**

个人提问也能使用同生辰的已有解读，提升参考资料的针对性。

- 例子：用户问事业变化，取本人记录的 career，必要时补充 wealth、move。
- 实现：先规范化排盘日、时辰索引、性别，再按 k 查缓存；未命中时只流式扫描对应年份，命中后保存有容量上限的记录缓存。
- 边界：仅覆盖 1950–2026；必须对齐换日、真太阳时、闰月和流派口径。找不到时继续用当前命盘与古籍，不能拿相邻生辰冒充。

**03. 离线的十三专题基础阅读｜P1｜成本：小**

没有模型服务时仍可阅读已有文本，减少固定内容的重复生成。

- 例子：切换总论、事业、财帛、迁移等专题，查看所选命盘的资料。
- 实现：先服务已缓存例盘，按专题折叠显示并提供来源、版本日期和问题入口；个人盘依赖精确查找。
- 边界：静态文字是 2026-10-15 版本的快照；时间相关句子要标明基准或隐藏，不能显示成实时运势。

**04. 跨专题的解释与追问｜P1｜成本：中**

支持一个问题关联多个宫位，回答更完整且控制上下文长度。

- 例子：换城市工作，分别检索事业、迁移、财帛的相关内容。
- 实现：把问题、所选宫位与专题映射到候选文本，按相关性与段落依赖取舍，保留否定词和成立条件。
- 边界：十三专题不是十三个互不相关的事实表；同一段文字不能重复拼入，多专题也不能自动推出新的应期。

**05. 学习笔记与可导出的阅读报告｜P1｜成本：小**

把一次学习过程保存为可回看的命盘、问答与引文记录。

- 例子：导出紫府同宫盘的学习笔记，保留用户选择的宫位和年度。
- 实现：记录当前排盘配置、问题、选用段落 ID、来源版本；报告分开呈现盘面事实、资料原文和解释。
- 边界：资料中固定的年份不能自动变成报告年份；发布时保留署名并处理单独授权的引文。

### 教学与知识

**06. 扩充有特点的教学例盘｜P1｜成本：中**

从十个例子扩展为按知识点组织的案例库。

- 例子：为三奇加会、空宫借星、身宫在官禄分别挑选正例和边界例。
- 实现：用当前引擎重排候选生辰，运行现有 41 个 detect 规则函数，再按教学特点、差异性和覆盖面挑选代表例。
- 边界：41 是代码规则函数数，不等于全部格局种数；样本的 ms 仅是命宫首颗主星，不能直接作为格局标签。

**07. 生辰变量对照实验｜P1｜成本：中**

让学习者观察时辰、性别或日期变化对盘面的影响。

- 例子：固定年月日，比较十二个时辰的命宫、身宫和四化关系。
- 实现：重新计算候选命盘，显示结构差异，再读取各自匹配的专题文字；突出保持不变和发生变化的条件。
- 边界：这是算法和理论的对照练习；没有真实事件标签，不能据此证明某个时辰才是当事人的真实出生时辰。

**08. 练习题、提示和答题讲解｜P1｜成本：中**

从看答案扩展为主动辨认星曜、宫位、四化和格局条件。

- 例子：让用户指出借星宫位，再逐步展示判断依据。
- 实现：正确答案由当前引擎或人工审定规则产生，样本文字仅辅助讲解；题目绑定生辰和配置。
- 边界：不能拿旧版解读中的一句话直接当标准答案；主观断语要保留条件和解释空间。

**09. 课程路径与个性化复习｜P2｜成本：中**

把案例按基础、宫位关联、四化、格局与运限分层组织。

- 例子：用户连续错判空宫借星，后续推荐结构不同的借星例盘。
- 实现：额外制作知识点与难度标签，记录答题表现，用案例索引挑选练习。
- 边界：数据没有课程难度或学习效果标签，需要产品另行设计；无需把全库文本塞入推荐模型。

**10. 补充星曜与宫位知识页面｜P1｜成本：中**

为当前空的 STAR_DB 内容框架提供可整理的素材和例证。

- 例子：天同化忌页面展示不同宫位条件下的例盘与出处。
- 实现：跨多个例盘提取共同概念，核对古籍与当前规则，人工整理通则、条件、反例及引用。
- 边界：一张盘的综合断语不能直接复制成通用星义；整理出的内容也不是恢复上游未公开的模板源码。

**11. 术语解释与古籍出处导航｜P1｜成本：中**

从具体例盘的术语进入对应书籍、章节和讲解。

- 例子：点击三方四正或某条引文，查看仓库内可核验的原文。
- 实现：抽取术语和引文标记，与现有古籍段落 ID 对齐；仅为核验成功的条目提供出处跳转。
- 边界：样本里的引文标签不代表出处已逐条核验；《天纪》引文有独立许可范围，不能作为普通 CC BY 文本整批再发布。

### 检索与比较

**12. 按盘面结构筛选案例库｜P1｜成本：大**

把 674,976 条生辰记录变成可按学习目标查找的例盘集合。

- 例子：筛选命宫空宫、身宫在官禄且某星化忌的候选盘。
- 实现：按批次调用当前排盘引擎，建立生辰键、命身宫、星曜、四化、格局及引擎版本索引，正文继续压缩存储。
- 边界：需要生成完整结构索引；样本本身没有十二宫结构，也不应将记录数称为互不重复的盘型数。

**13. 相似命盘与差异解释｜P2｜成本：大**

在已有例盘之外，找结构接近但关键条件不同的教学对照。

- 例子：同为武贪同宫，比较是否有火铃、四化与辅煞的区别。
- 实现：优先用结构化特征定义相似度，再附相关文字；展示相似条件与不同条件，保留准确生辰来源。
- 边界：文本相似常来自同一模板，不能当命盘结构相似；相似盘也不能充当用户本人的匹配结果。

**14. 专题段落搜索与知识检索｜P2｜成本：大**

检索某个术语或条件涉及的资料，供解释和研究使用。

- 例子：搜索化禄入财，查看相关段落以及对应例盘。
- 实现：先做精确段落去重、建立段落到生辰和专题的引用关系，再考虑全文索引；语义向量检索放到有需求时。
- 边界：1990 年的 98.60% 是精确段落重复出现率，含标题和套话；不能直接推算全库唯一知识量或压缩后的索引大小。

**15. 合盘中的双方背景资料｜P2｜成本：中**

为已有合盘解释补充双方各自的感情、性格等资料。

- 例子：并列展示两人的 love 和 personality 相关片段，再由现有合盘规则分析。
- 实现：分别精确查找两条记录，明确标记人物归属和来源，由独立合盘规则处理关系判断。
- 边界：数据只有单盘解读，没有配对结果或相处事实，不能从两段文本直接制造匹配分数或关系结论。

**16. 白话、繁简与多语言辅助阅读｜P2｜成本：中**

让不同基础的学习者理解同一份资料。

- 例子：保留古典术语，旁边展示白话解释或英文术语表。
- 实现：按已选段落转换，维护术语表，保存原文与转换稿对应关系；为已校对内容缓存结果。
- 边界：翻译或改写不会提高原始断语的可靠性；不得丢掉条件、否定和原文来源。

### 工程与质量

**17. 引擎升级与解读冲突检查｜P0｜成本：中**

发现当前盘面与旧文本的矛盾，避免错误资料进入问答。

- 例子：现有天同化忌例盘：当前引擎亮度为平，样本写庙旺。
- 实现：固定例盘和配置，把可核验的星曜、四化、亮度、时间句做对照；保留版本差异记录，冲突段落排除或明确展示。
- 边界：样本文字是旧版本基线，不是金标准；已观测到差异，不能只靠提示词要求模型忽略就算解决。

**18. 生辰、字段与边界回归检查｜P1｜成本：中**

检查查找服务对日期、时辰和缺失记录的处理。

- 例子：验证闰日、十二时辰边界、1950/2026 边界和超范围生辰。
- 实现：用清单校验数量与文件完整性，抽检键的唯一性、十三专题完整度；对排盘口径单独做转换测试。
- 边界：全库数量目前按 MANIFEST 汇总；只有 1990 年完成逐条语义结构扫描，不能宣称全库内容都无误。

**19. 问答检索、引用和上下文评测｜P0｜成本：中**

验证新增资料是否真正改善回答，并检查串盘和时间错误。

- 例子：问 2027 年事业时，不得把样本固定的 2026 年当前大限当成结论。
- 实现：建立小型人工审定题集，评估生辰命中、专题相关性、引用可追溯性、冲突处理和上下文长度；对照接入前后。
- 边界：模型答案与模板文字相似不等于正确；不以预测准确率或真实事件命中率作为本数据能提供的指标。

**20. 原生应用的离线学习资料包｜P1｜成本：中**

桌面和移动端可带少量教学内容，联网或按需再加载更多资料。

- 例子：首包附十张例盘，用户选择后读取本地专题文字。
- 实现：通过宿主适配层加载带版本与校验的课包；需要时支持可删除的年份包或记录包。
- 边界：Web 的 Node 文件读取不能直接搬进共享 React 或移动端；首包不必附全量归档，缓存须有容量控制。

**21. 压缩归档加按需缓存服务｜P0｜成本：中**

在保留 161.49 MB 完整资料的同时支持少量热点盘读取。

- 例子：第一次查某个生辰流式读取对应年，后续从小缓存直接获取。
- 实现：先使用十盘缓存；通用服务以年份定位、后台顺序解码、结果缓存、并发合并和取消超时为基础，按版本区分缓存。
- 边界：tar 偏移只能定位年份；普通 zstd 流不能直接跳到任意生辰。缓存会增长，解码也需要内存，生产负载仍需实测。

**22. 段落去重与可随机读取的派生存储｜P2｜成本：大**

当使用量扩大后，降低反复扫年份的成本并支撑搜索。

- 例子：同一段知识只存一份，多个生辰通过引用表关联。
- 实现：流式处理归档，按段落精确去重、保留顺序和引用条件；或按记录独立压缩建立索引，先在一年数据上评估存储和查询。
- 边界：派生库可能比原始 161 MB 归档更大；不得假设去重一定使总磁盘更小，也不能打乱上下文依赖。

### 模型与研究

**23. 清洗后的微调与蒸馏研究｜P3｜成本：大**

未来可研究固定讲解风格和术语表达，减少重复的长提示。

- 例子：用已校对的结构事实与讲解样本训练辅助教学模型。
- 实现：去重、移除过时应期和冲突断语、补齐当前结构数据与来源标签；按模板/格局/日期组划分训练与测试，保留独立人工评测。
- 边界：现有条目不是现成的多轮问答；模板重复会造成数据泄漏。训练不会恢复私有源码，也不应吞入许可另列的引文。

**24. 盘面结构分布与教学覆盖研究｜P2｜成本：中**

分析哪些结构已被课程覆盖，哪些边界条件缺少例子。

- 例子：统计候选盘中的空宫、主星组合与格局条件，挑选覆盖更广的练习。
- 实现：使用当前引擎生成的结构索引，明确统计单位、年份和配置；按特征覆盖选择代表样本。
- 边界：日期×时辰×性别的均匀枚举不是现实出生人口分布；频率不能解释为真实人群比例，更不代表命运发生率。

## 具体到“提问时带哪些资料”

建议每次问答组合以下内容：

1. 用户当前问题，以及已经完成的历史问答。
2. 当前引擎生成的完整命盘结构、排盘口径和用户选中的宫位、四化、本命／大限／流年及年份。
3. 学习页面的例盘说明与知识点。
4. 同生辰记录中与问题相关的少量专题段落，附出生键、专题、内容版本、段落 ID、来源和是否删减等信息。
5. 已有古籍检索命中的可核验条目；样本解读与古籍原文分开标识。

例如“换城市工作适合吗”：优先查同生辰的 career、move，必要时补充 wealth。当前命盘和所选运限负责盘面事实，样本提供解释线索，古籍提供可追溯依据。问题如果只是询问一个术语，可以主要使用术语和古籍资料，不必强制读取个人样本。

先按生辰匹配，再按专题与段落选择。十三篇全文只是候选资料，不是每次必须发送的内容。应对重复、冲突和时间句做显式处理，并给新资料独立的长度预算；具体预算通过真实模型上下文容量与小题集评测确定。当前应用保留完整对话历史，不能因为新增资料而静默截掉旧问题。

获取不到、超时、超出年份范围或存在无法判断的口径差异时，保持当前命盘与现有古籍问答可用，明确参考资料是否命中。其他生辰的案例若被引用，必须清楚标成比较例子，不能当成本人的资料。

## 建议的技术边界

**存储与读取。** 完整 tar 保留在 data/datasets；十盘缓存优先。通用查找服务只扫描所需年份，命中记录后写入按版本区分、带容量上限的缓存，合并相同键的并发查找，并限制解码并发和执行时间。未经清洗的源文件保持可核验。后续流量需要时再建立每记录压缩索引或去重段落库；这些派生库可能比现有归档更大，应先在单年数据上衡量收益。

**Web。** [解读路由](/Users/wanghongfei/work/work-space/ziwei-doushu/apps/web/app/api/interpret/route.ts) 目前将共享 interpretMessages 交给 [handleAIRequest](/Users/wanghongfei/work/work-space/ziwei-doushu/apps/web/lib/ai/server.ts)，buildMessages 是同步返回数组的函数。文件检索应放进服务端适配层，并增加异步资料注入边界，不能把文件读取塞进共享 React 组件或假定已有磁盘检索入口。

**原生端。** [native.ts](/Users/wanghongfei/work/work-space/ziwei-doushu/apps/native/src/adapters/native.ts) 在共享消息构建后走 Tauri 流式接口。应通过宿主能力加载少量内置课包或可选缓存；Web 的 Node 文件系统代码不能直接用于 Android/iOS。共享层只接收经过校验的资料结构。

**上下文可信度。** 参考段落作为数据传入，不作为系统指令；客户端不能任意伪造“官方参考资料”。学习例盘继续由已有目录和引擎重新生成。当前命盘可验证的结构事实优先于样本文字，条件性结论不得截掉前提。来源链接只能指向确实存在的条目。

**部署。** 本地 data 目录已经被 Git 忽略，当前 Web 独立部署文件追踪也排除了该目录。本机下载不等于远程部署自带数据；后续可单独挂载压缩归档，或只部署清洗后的教学课包。

## 推荐的四个阶段及验收方式

1. **先完成十盘学习资料接入。** 清洗十条缓存；按问题选段；展示来源；处理当前亮度与旧快照冲突。检查十盘不会串盘，切换例盘或年份后不会带入旧选择，新增引用可追溯，缓存体积可控。
2. **再支持个人盘。** 规范出生键，建设按年份读取和有界缓存；检查闰日、时辰、换日、超范围、取消、缓存失效和并发行为。测量冷查与缓存命中的真实耗时后决定是否进一步建索引。
3. **有检索需求时扩展学习库。** 通过当前引擎生成版本化结构标签，选择有区分度的例子，再做练习与全文搜索。验证筛选条件与实际盘面一致，去重不丢掉段落来源和成立条件。
4. **最后才考虑模型训练。** 准备清洗过的样本、许可标记与人工审定评测集，按模板和结构分组隔离训练／测试。先证明相对现有检索问答有收益，再扩大投入。

## 不足以单独完成的用途

- **实时运限预测系统**：这份文本不包含用户任意所选年份的完整动态盘，也不提供流月／流日／流时排盘能力。
- **准确率、真实人生事件或医学结果验证**：没有观测标签，生成断语与模型互相一致不能证明现实预测有效。
- **真实出生时辰鉴定**：可以比较候选盘的结构和解释，不能凭模板相似度证明哪个时辰为真。
- **合盘匹配分数**：缺少成对关系样本和结果；只能补充双方各自的资料。
- **完整恢复未公开后端**：数据保存了部分输入范围内的输出，不包含原模板源码、全部推导条件或在线后台功能。
